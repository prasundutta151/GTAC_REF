Section 1: Submitter Profile

The submitter profile establishes the identity of the researcher completing the form. It captures contact details, institutional affiliation, career stage, and academic expertise.

Field Name Type & Source Behavior & Validation Rules
1. Your Name Text Input Required. Honorific titles (Dr, Prof, etc.) are automatically stripped. If review volunteering is active, changes synchronize in real time to Referee Block 1.
2. Your Email ID Email Input Required. Automatically validated in real time via Gemini AI / domain heuristics. Renders a green ✓ Validated email pill showing verified institutional status.
3. Your Affiliation Dynamic Dropdown Populated from database/affiliations.txt. Includes + Others option. When selected, expands an additional text box allowing registration of new institutions into the database.
4. Your Career Status Dropdown Populated from database/career_status.txt (Undergraduate, PhD Student, Postdoctoral Fellow, Faculty Member, Scientist, Engineer, Others).
5. Your Expertise Interactive Multi-Select Dropdown Powered by ExpertisePicker. Selecting an astronomy/physics topic from the list adds an interactive tag chip with a remove button. Includes + Others to register new sub-fields.

Question 6: GTAC Review Volunteering

Determines whether the submitter wishes to volunteer as a peer referee for proposal cycles.

Dynamic Cycle Loading: Instead of static text ("This cycle:"), the label dynamically displays For Cycle: 52 loaded directly from database/cycle.txt at runtime.

Volunteering Options:

  • For Cycle: [Cycle Number] (Yes / No radio)
  • Future cycles (Yes / No radio)

Automated Synchronization Rule:

If the submitter selects "Yes" for either the current cycle or future cycles:

  1. The system automatically creates or designates Referee Suggestion - 1 as the submitter's own entry.
  2. The card is tagged with badge Self - Review Volunteer (Locked).
  3. Submitter fields from Section 1 are mirrored into the card.
  4. If the user switches both back to "No", the block is unlocked and converted back to an editable entry.

Full-Length Dark Background Bar

The interface features a full-width dark gradient button positioned directly beneath the list of referee cards, guaranteeing it always follows the last ongoing referee block.

State 1: Initial Click (Own Entry)

When zero referee cards are present, the bar displays:

＋ Add Referee Suggestion (Own Entry)

Clicking creates Block 1 pre-populated with the submitter's profile details.

State 2: Subsequent Clicks (Others Entry)

When one or more cards already exist, the bar adapts to:

＋ Add Referee Suggestion (Others Entry)

Clicking appends blank referee cards for suggesting external peer reviewers.

Referee Suggestion Cards & Real-Time Lookup

Each referee card requires Name, Email, Affiliation, Career Status, and Expertise. As the user enters details, intelligent cross-checking against Referee_database_A occurs:

1. Title Stripping

When entering a referee name like Prof. Jayaram Chengalur or Dr. Nirupam Roy, the system strips the honorific prefix in real time and normalizes the name to Jayaram Chengalur or Nirupam Roy.

2. Half-Initials Matching

Names entered with initials (e.g. Y. Gupta, J. Chengalur, P. Dutta, or Gupta, Y.) are matched against full database records where the surname matches and given initials correspond.

3. Real-Time Pre-Filling & Badges

  • Verified Referee in DB: Displays Verified in DB and pre-fills email, affiliation, and expertise tags from the database record.
  • Suggested Referee in DB: Displays Already in DB with pre-filled fields.
  • New Referee Suggestion: Displays New Suggestion. On submission, a new unique REF_XXXX ID is sequentially assigned.

4. Input Editability Guarantee

Always Editable: Even when a referee is verified in the database or validated by Gemini, all inputs remain completely editable. Reviewers' names, emails, and institutions are never locked into a disabled state, allowing users to make adjustments whenever necessary.

Gemini AI Auto-Validation

By default, entering a referee's name or email automatically triggers validation:

  • Live Verification: If GEMINI_API_KEY is set, calls Gemini 1.5 Flash to verify academic standing and institutional affiliation.
  • Offline Heuristics: If offline or without an API key, verifies against recognized Indian and international astronomy institutions (NCRA-TIFR, IUCAA, RRI, IISc, TIFR, IIA, PRL, ARIES, IITs, etc.) and academic top-level domains.
  • Visual Feedback: Displays ✓ Validated email with verified domain confirmation underneath the input field.

Post-Submission Summary Modal

Upon submission, the system presents a clean, beautifully organized dialog summarizing all provided information:

  1. Header: Submission Reference ID (e.g. SUB_1789130888) and formatted submission date/time.
  2. Submitter Profile: Full name, validated email, institutional affiliation, career level, and expertise tags.
  3. Review Volunteering: Availability for Cycle 52 and Future Cycles.
  4. Referee Suggestions: Individual cards for each suggested referee with unique ID (REF_XXXX), type tag (Own Entry / Peer Referee), Name, Validated Email, Affiliation, Career Status, and Expertise.
  5. Zero File Path Leaks: Internal server storage details (e.g. database/Referee_database_A.csv) are hidden to maintain a clean user experience.
