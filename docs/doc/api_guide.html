Backend REST API Reference

The backend API is implemented in dev/server.py using Python 3's built-in standard library. It requires zero external dependencies and handles all database queries and submissions.

GET /api/database

Retrieves a complete snapshot of the system taxonomies and current referee database.

curl -s http://localhost:8080/api/database

Response (200 OK):

  "cycle": "52",
  "affiliations": [
    { "id": "AFF_001", "label": "National Centre for Radio Astrophysics (NCRA-TIFR), Pune" },
    ...
  ],
  "expertise": [
    { "id": "EXP_01", "label": "Pulsars, Transients and Fast Radio Bursts" },
    ...
  ],
  "career_status": [
    { "id": "CAR_01", "label": "Undergraduate Student" },
    ...
  ],
  "referees": [
    {
      "unique_id": "REF_0001",
      "referee_name": "Yashwant Gupta",

      "expertise": "EXP_01;EXP_14",
      "career_status": "CAR_04",
      "referee_status": "verified",

}

GET /api/cycle (and /cycle.txt)

Returns the current GTAC proposal cycle number as plain text.

curl -s http://localhost:8080/api/cycle

Response:

52

GET /api/referees/lookup

Cross-checks names and emails against Referee_database_A using both substring matching and fuzzy half-initials matching with full surname.

curl -s "http://localhost:8080/api/referees/lookup?q=Y.+Gupta"

Response:

{
  "matches": [
    {
      "unique_id": "REF_0001",
      "referee_name": "Yashwant Gupta",
      "email": "ygupta@ncra.tifr.res.in",
      "affiliation": "AFF_001",
      "expertise": "EXP_01;EXP_14",
      "career_status": "CAR_04",
      "referee_status": "verified",
      "available": "true"
    }
  ]
}

POST /api/gemini-validate

Validates a researcher's Name and Email address using Gemini AI or academic institutional domain heuristics.

curl -s -X POST http://localhost:8080/api/gemini-validate \
  -H "Content-Type: application/json" \
  -d '{"name": "Jayaram Chengalur", "email": "chengalur@ncra.tifr.res.in"}'

Response:

{
  "valid_email": true,
  "mention": "Validated email",
  "message": "Validated email: Verified institutional domain (ncra.tifr.res.in)",
  "affiliation": "AFF_001",
  "email_domain": "ncra.tifr.res.in",
  "expertise": ["EXP_01", "EXP_03", "EXP_11", "EXP_14"],
  "clean_name": "Jayaram Chengalur",
  "email": "chengalur@ncra.tifr.res.in",
  "source": "Smart Knowledge Base"
}

POST /api/submit

Processes a complete form submission, dynamically registering new institutions and assigning sequential REF_XXXX identifiers.

curl -s -X POST http://localhost:8080/api/submit \
  -H "Content-Type: application/json" \
  -d '{
    "user_name": "Prasun Dutta",
    "user_email": "pdutta@iucaa.in",
    "user_affiliation": "AFF_002",
    "user_career_status": "CAR_04",
    "user_expertise": ["EXP_02", "EXP_07"],
    "review_this_cycle": "yes",
    "review_future_cycles": "no",
    "referees": [
      {
        "name": "Prasun Dutta",
        "email": "pdutta@iucaa.in",
        "affiliation": "AFF_002",
        "career_status": "CAR_04",
        "expertise": ["EXP_02", "EXP_07"],
        "is_self": true
      }
    ]
  }'

Response:

{
  "status": "success",
  "submission_id": "SUB_1789131000",
  "assigned_referee_ids": ["REF_0011"]
}

Developer CLI Reference (util)

The repository includes an executable Python CLI script util in the project root to automate project maintenance, deployment, and version management.

Command & Flags Description
./util --serve [PORT] Starts the local HTTP REST server (default: port 8080).
./util --version [VER] Increments minor patch version (01.00.XX) or sets explicit version.
./util --git-push [-m MSG] Stages all project files, commits with structured message, and pushes to remote.
./util --sync-docs Synchronizes code, assets, and guides into docs/ for GitHub Pages.
./util --wiki-push [WIKI_URL] Pushes markdown documentation in wiki/ to the GitHub Wiki repository.
./util --change-branch [BR] Lists existing git branches or switches to a target branch.
./util --release Builds a standalone release tarball in versions/ excluding dev/git files.
./util --status Displays the current active version, git branch, and working tree health.

🚀 Production Deployment & Central Database Setup Options

On GitHub Pages, the GTAC Referee Form operates as an ultra-fast client application: taxonomies and referee records are read instantly, and submissions are stored in the user's browser session (localStorage). To collect all proposal submissions and referee registrations into an authoritative, central database (database/Referee_database_A.csv and database/form_submissions.csv), administrators can select from four production deployment models:

Option 1: NCRA / Institutional Linux Server (Recommended)

Deploy server.py directly on an NCRA-TIFR virtual machine or internal server behind an Nginx reverse proxy with SSL encryption.

1. Systemd Service Configuration (/etc/systemd/system/gtac-ref.service)

[Unit]
Description=GTAC Referee System REST API Service
After=network.target

[Service]
Type=simple
User=gtac
WorkingDirectory=/var/www/GTAC_REF
ExecStart=/usr/bin/python3 dev/server.py 8080
Restart=always
RestartSec=5
Environment=PYTHONUNBUFFERED=1
Environment=GEMINI_API_KEY=your_optional_gemini_api_key

[Install]
WantedBy=multi-user.target

Enable and start the service:

sudo systemctl daemon-reload
sudo systemctl enable --now gtac-ref.service
sudo systemctl status gtac-ref.service

2. Nginx Reverse Proxy with SSL (/etc/nginx/sites-available/gtac-ref)

server {
    server_name gtac-ref.ncra.tifr.res.in;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    listen 443 ssl;
    ssl_certificate /etc/letsencrypt/live/gtac-ref.ncra.tifr.res.in/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/gtac-ref.ncra.tifr.res.in/privkey.pem;
}

Option 2: Cloud Container Deployment (Render / Railway / Docker)

Package the application into a Docker container and host it on cloud platforms like Render, Railway, Fly.io, or PythonAnywhere. Ensure a persistent disk volume is mounted to /app/database so CSV records persist across restarts.

1. Dockerfile

FROM python:3.11-slim
WORKDIR /app
COPY . /app
VOLUME ["/app/database"]
EXPOSE 8080
CMD ["python3", "dev/server.py", "8080"]

2. Build and Run Container

docker build -t gtac-ref-backend .
docker run -d \
  -p 8080:8080 \
  -v /var/gtac_data:/app/database \
  --name gtac-ref \
  --restart unless-stopped \
  gtac-ref-backend

Option 3: Direct GTAC Secretariat Email & JSON Dispatch

For organizations that wish to avoid hosting an always-on public server, the web form can run 100% statically on GitHub Pages while dispatching submissions directly to the committee:

  • Automated JSON Download: Upon clicking Submit, the client generates and downloads a validated file named submission_SUB_XXXXXX.json.
  • Secretariat Mailto Link: The form opens the submitter's native email client with pre-filled subject [GTAC Cycle 52] Proposal Referee Submission addressed to gtac@ncra.tifr.res.in.
  • Zero Server Maintenance: Eliminates firewall configurations, SSL renewals, and cloud hosting bills.

Option 4: GitHub Actions & Webhook Automation

Connect form submissions to a GitHub Actions webhook or serverless endpoint (e.g. Cloudflare Worker or AWS Lambda). When a researcher submits recommendations:

  • The webhook receives the JSON submission payload and triggers a GitHub Actions workflow (repository_dispatch).
  • The GitHub Action runs a Python ingestion script that updates Referee_database_A.csv and form_submissions.csv.
  • The action creates a commit directly on a private administrative branch or opens a Pull Request for GTAC Chair review.
  • Maintains a cryptographically verified Git history for every referee nomination.
Connecting the Frontend to your Production Backend:
In dev/app.js, configure the remote backend URL at the top of the file: 
const API_BASE_URL = window.location.hostname === 'localhost' 
  ? '' 
  : 'https://gtac-ref.ncra.tifr.res.in'; // Your production server URL
