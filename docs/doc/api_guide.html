Backend REST API Reference

The backend API is implemented in dev/server.py using Python 3's built-in standard library. It requires zero external dependencies and handles all database queries and submissions.

GET /api/database

Retrieves a complete snapshot of the system taxonomies and current referee database.

curl -s http://localhost:8080/api/database

Response (200 OK):

  "affiliations": [

    ...

  "expertise": [

    ...
  ],

    { "id": "CAR_01", "label": "Undergraduate Student" },

GET /api/cycle (and /cycle.txt)

Returns the current GTAC proposal cycle number as plain text.

curl -s http://localhost:8080/api/cycle

Response:

52

GET /api/referees/lookup

Cross-checks names and emails against Referee_database_A using both substring matching and fuzzy half-initials matching with full surname.

curl -s "http://localhost:8080/api/referees/lookup?q=Y.+Gupta"

Response:

{
  "matches": [
    {
      "unique_id": "REF_0001",
      "referee_name": "Yashwant Gupta",
      "email": "ygupta@ncra.tifr.res.in",
      "affiliation": "AFF_001",
      "expertise": "EXP_01;EXP_14",
      "career_status": "CAR_04",
      "referee_status": "verified",
      "available": "true"
    }
  ]
}

POST /api/gemini-validate

Validates a researcher's Name and Email address using Gemini AI or academic institutional domain heuristics.

curl -s -X POST http://localhost:8080/api/gemini-validate \
  -H "Content-Type: application/json" \
  -d '{"name": "Jayaram Chengalur", "email": "chengalur@ncra.tifr.res.in"}'

Response:

{
  "valid_email": true,
  "mention": "Validated email",
  "message": "Validated email: Verified institutional domain (ncra.tifr.res.in)",
  "affiliation": "AFF_001",
  "email_domain": "ncra.tifr.res.in",
  "expertise": ["EXP_01", "EXP_03", "EXP_11", "EXP_14"],
  "clean_name": "Jayaram Chengalur",
  "email": "chengalur@ncra.tifr.res.in",
  "source": "Smart Knowledge Base"
}

POST /api/submit

Processes a complete form submission, dynamically registering new institutions and assigning sequential REF_XXXX identifiers.

curl -s -X POST http://localhost:8080/api/submit \
  -H "Content-Type: application/json" \
  -d '{
    "user_name": "Prasun Dutta",
    "user_email": "pdutta@iucaa.in",
    "user_affiliation": "AFF_002",
    "user_career_status": "CAR_04",
    "user_expertise": ["EXP_02", "EXP_07"],
    "review_this_cycle": "yes",
    "review_future_cycles": "no",
    "referees": [
      {
        "name": "Prasun Dutta",
        "email": "pdutta@iucaa.in",
        "affiliation": "AFF_002",
        "career_status": "CAR_04",
        "expertise": ["EXP_02", "EXP_07"],
        "is_self": true
      }
    ]
  }'

Response:

{
  "status": "success",
  "submission_id": "SUB_1789131000",
  "assigned_referee_ids": ["REF_0011"]
}

Developer CLI Reference (util)

The repository includes an executable Python CLI script util in the project root to automate project maintenance, deployment, and version management.

Command & Flags Description
./util --serve [PORT] Starts the local HTTP REST server (default: port 8080).
./util --version [VER] Increments minor patch version (01.00.XX) or sets explicit version.
./util --git-push [-m MSG] Stages all project files, commits with structured message, and pushes to remote.
./util --sync-docs Synchronizes code, assets, and guides into docs/ for GitHub Pages.
./util --wiki-push [WIKI_URL] Pushes markdown documentation in wiki/ to the GitHub Wiki repository.
./util --change-branch [BR] Lists existing git branches or switches to a target branch.
./util --release Builds a standalone release tarball in versions/ excluding dev/git files.
./util --status Displays the current active version, git branch, and working tree health.
